# update-adrスキルの詳細

git logから、アーキテクチャ決定記録（ADR）ドキュメントを `@docs/ADR.md` として作成せよ。`docs/`ディレクトリが存在しない場合は作成せよ。すでに `docs/ADR.md` が存在する場合は、git logの内容をもとに更新せよ。

## ADR作成の対象とする範囲

コミット済みの内容のみ反映せよ。未コミットの変更は反映するな。

## 決定の抽出基準

コミット済みのコミットメッセージ及びコミットの内容から、アーキテクチャ決定に関する内容を抽出せよ。

## ADRのフォーマット

ADRは以下のフォーマットに従って作成せよ。

```
---

## ADR-{%03d}: {ADRのタイトル} — {概要}

**Date**: YYYY-MM-DD (initial commit `{commit-hash}` onward)
**Status**: {ステータス: Accepted | Deprecated | Superseded | Rejected | Proposed} 

**Context**: {文脈: なぜその決定が下されたのか、それによってどのような問題が解決されるのか、どのような代替案が検討されたのか}

**Decision**: {決定: 何が決定されたか、それがどのように実装されるか、どのようなトレードオフが行われたか}

**Consequences**: {結果: その決定がもたらす影響、メリット、デメリット、将来的な課題}

**Update-{%03d} ({YYYY-MM-DD}, `{commit-hash-N}`, `{commit-hash-N+1}`, ...)**: {更新: その決定がどのように変更されたか、なぜ変更されたのか、どのような代替案が検討されたのか}

``` 

## ルール

1. コミットの後に自動で実行するな。
2. 既存のADRの内容を変更する場合は、必ず更新履歴として追記せよ。
3. 新しいADRを作成する場合は、既存のADRの番号を引き継ぎ、更新履歴として追記せよ。
4. 番号は昇順に付与せよ。
